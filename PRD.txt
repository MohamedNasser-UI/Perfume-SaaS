# PRD — Perfume Customization Sales Outlet System

**Version:** 1.0 — MVP
**Initial Deployment:** One outlet
**Currency:** EGP
**System Type:** Retail POS + Custom Perfume Configuration + Inventory + Procurement + Supplier Ledger + CRM

---

## 1. Executive Summary

The system is a **Perfume Customization Sales Outlet Management System** designed for an outlet that sells:

1. Customized perfumes prepared at the outlet.
2. Original ready-made perfumes.
3. High-copy ready-made perfumes.

The system connects the full operational cycle:

**Procurement → Inventory → Perfume Configuration → Sales → Consumption → Customer History → Supplier Balances → Returns → Finished Inventory**

The MVP will initially support **one physical outlet**. Multiple users can operate the outlet, and all users will initially have full access.

The system must be configuration-driven so the owner can change pricing, markup, concentration percentages, discounts, products, suppliers, bottles, packaging, and other business parameters without modifying the application.

---

# 2. Business Objectives

The system should:

* Eliminate manual sales calculations.
* Track all purchased components.
* Maintain accurate on-hand inventory.
* Automatically calculate component consumption when a customized perfume is sold.
* Calculate weighted-average inventory cost.
* Calculate selling price using cost + configurable markup.
* Maintain supplier balances and statements.
* Record supplier payments.
* Track waste, damage, and spillage.
* Maintain customer profiles.
* Use Egyptian mobile number as the unique customer identifier.
* Store complete customer purchase history.
* Allow salespeople to reproduce previous perfume configurations.
* Support customer-supplied bottles.
* Support original and high-copy ready-made perfumes.
* Support returns.
* Convert returned customized perfumes into finished inventory.
* Provide profitability and operational reporting.
* Prepare the architecture for future online sales and multiple outlets.

# 11. Stabilizer

Stabilizer is optional.

The salesperson can manually add it to a customized perfume.

The salesperson enters the quantity.

Example:

100ml perfume:

* Oil = 25ml
* Stabilizer = 2ml
* Alcohol = 73ml

Therefore:

**25 + 2 + 73 = 100ml**

The system must prevent the total formula from exceeding the selected bottle volume.

# 17. Standard Recipe Calculation

The system calculates standard oil quantity based on:

**Bottle Size × Oil Concentration %**

Example:

100ml EDP:

**100 × 20% = 20ml oil**

Without stabilizer:

**100 − 20 = 80ml alcohol**

Therefore:

> Oil = 20ml
> Alcohol = 80ml

---

# 18. Oil Quantity Override

The standard recipe is only the default.

The salesperson can change the oil quantity.

Example:

Standard 100ml EDP:

> Oil = 20ml

Customer requests stronger perfume.

Salesperson enters:

> Oil = 25ml

The system automatically recalculates:

> Alcohol = 75ml

If stabilizer = 2ml:

> Alcohol = 73ml

The formula always remains:

**Oil + Stabilizer + Alcohol = Bottle Size**

The system must preserve both:

* Standard oil quantity
* Actual oil quantity

and identify that an override occurred.

# 24. Pricing Engine

The MVP uses:

**Selling Price = Cost × (1 + Markup %)**

There is currently one global markup.

There are no different markup rules for:

* Oils
* Bottles
* Product categories
* Concentrations

Example:

Material cost:

> 214 EGP

Markup:

> 50%

Selling price:

**214 × 1.50 = 321 EGP**

---

# 25. Cost Calculation

Customized perfume cost is based on the weighted-average cost of consumed components.

Example:

| Component |  Qty | Avg Cost |        Cost |
| --------- | ---: | -------: | ----------: |
| Oil       | 20ml |  5.25/ml |         105 |
| Alcohol   | 80ml |  0.80/ml |          64 |
| Bottle    |    1 |       30 |          30 |
| Pump      |    1 |        5 |           5 |
| Box       |    1 |       10 |          10 |
| **Total** |      |          | **214 EGP** |

The MVP considers this the **material cost**.

Labor and overhead are not included initially.

---

# 26. Weighted-Average Cost

After every purchase receipt:

**New Average Cost =**

`(Existing Quantity × Existing Average Cost + New Quantity × New Unit Cost) / New Total Quantity`

Example:

Existing inventory:

> 1,000ml @ 5 EGP/ml

Value:

> 5,000 EGP

New purchase:

> 1,000ml @ 5.50 EGP/ml

Value:

> 5,500 EGP

New inventory:

> 2,000ml

New value:

> 10,500 EGP

Weighted-average:

**10,500 / 2,000 = 5.25 EGP/ml**

A 20ml consumption therefore has a material cost of:

**20 × 5.25 = 105 EGP**

# 41. Customized Returns

Customized perfume returns are handled differently.

The returned perfume should **not** be broken back into:

> Oil + Alcohol + Stabilizer

Instead, it becomes a finished customized perfume item.

Example:

Returned perfume:

> 100ml
> Oud
> EDP
> 25ml Oil
> 73ml Alcohol
> 2ml Stabilizer
> Bottle B01
> Pump P01

The system creates:

> **Finished Customized Inventory +1**

The exact recipe remains attached to the finished item.

# 46. Transaction Atomicity

A completed sale must update all relevant records together.

* Sales order
* Sales lines
* Payment

* Customized configuration

If one critical step fails, the transaction should not be partially posted.

* Purchase invoices
* Supplier payments
* Returns

# 47. Core Inventory Formula

For every item:

**On Hand = Opening + Purchases + Returns − Sales Consumption − Waste ± Adjustments**

This should be reconcilable to the inventory ledger.

---

# 48. Supplier Balance Formula

**Supplier Balance = Opening Balance + Purchases − Payments ± Adjustments**

Every supplier balance must be traceable to individual transactions.

---

# 49. Profit Calculation

For each sale:

**Gross Profit = Selling Revenue − Material Cost**

**Gross Margin % = Gross Profit / Selling Revenue × 100**

Example:

Selling price:

> 321 EGP

Material cost:

> 214 EGP

Gross profit:

> 321 − 214 = **107 EGP**

Gross margin:

> 107 / 321 × 100 = **33.33%**

This is before operating expenses, salaries, rent, utilities, payment fees, etc.

# 64. Key Business Validations

The system must prevent:

### Invalid recipe

`Oil + Stabilizer + Alcohol > Bottle Size`

### Duplicate customer

Same normalized Egyptian mobile number.

### Negative inventory

Unless a future configuration explicitly enables it.

### Invalid bottle/pump

Pump must be compatible with selected bottle.

### Invalid discount

Discount must exist in the configured discount list.

### Invalid payment

Payment method must be one of the configured methods.

### Invalid purchase

Purchase quantity and unit cost must be greater than zero.

# 65. Audit Trail

Important events must store:

* User
* Date
* Time
* Transaction
* Previous value
* New value where relevant

Examples:

> User changed markup from 50% → 55%.

> User changed oil quantity from 20ml → 25ml.

This is particularly important because all users initially have full access.

```text
                    ┌─────────────────┐

                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │ PURCHASE INVOICE│
                    └────────┬────────┘
                             │
                    ┌────────▼────────┐
                    │    INVENTORY    │
                    │ Weighted Average │
                    └────────┬────────┘
                             │
             ┌───────────────┴────────────────┐
             │                                │
             ▼                                ▼
    ┌─────────────────┐             ┌──────────────────┐
    │ CUSTOMIZED SALE │             │ READY-MADE SALE  │
    └────────┬────────┘             └─────────┬────────┘
             │                                │
             ▼                                ▼
    ┌─────────────────┐             ┌──────────────────┐
    │ Oil + Alcohol   │             │ Finished Product │
    │ + Stabilizer    │             │ Inventory        │

    │ + Pump + Box    │                       │

                   └────────┬─────────┘
                            │
                 ┌──────────┴───────────┐
                 ▼                      ▼
        ┌─────────────────┐    ┌─────────────────┐
        │ CUSTOMER / CRM  │    │    PAYMENT      │
        │ Purchase History│    │ Cash/Visa/      │
        │ Preferences     │    │ Instapay        │
        └─────────────────┘    └─────────────────┘
                            │
                            ▼
                   ┌──────────────────┐
                   │ RETURN / RESALE  │
                   └────────┬─────────┘
                            │
                            ▼
              ┌─────────────────────────────┐
              │ FINISHED CUSTOMIZED STOCK   │
              │ Available for Future /      │
              │ Online Sales                │
              └─────────────────────────────┘
```

## Core principle

The system should maintain **three connected but distinct layers**:

**1. Component Inventory**

> Oil, alcohol, stabilizer, bottles, pumps, boxes.

**2. Finished Inventory**

> Original, high-copy, and returned/customized finished perfumes.

**3. Transaction History**

> Purchases, sales, recipes, consumption, returns, waste, supplier balances, payments, and customer history.

That separation is what will allow the outlet to start simple today while eventually becoming a **multi-channel perfume business with physical and online sales without having to rebuild the inventory and costing engine**.
